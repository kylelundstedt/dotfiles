# rclone filter for the home/ backup (paths relative to ~). First match wins.
# Junk + dev regenerables (excluded everywhere, incl. under Mobile Documents).
# Bare names (no leading /) match at every level, incl. the root (unlike **/x,
# which misses root-level files).
- .DS_Store
- *.sock
- **/node_modules/**
- **/.venv/**
- **/venv/**
- **/__pycache__/**
- **/.mypy_cache/**
- **/.pytest_cache/**
- **/.next/**
- **/dist/**
- **/build/**
- **/target/**
# iCloud exclusions first (first match wins). Evicted/dataless items anywhere
# under Mobile Documents fail with 'resource deadlock avoided' on read and
# rc=1 the whole home sync. Two classes bitten so far: the iCloud trash
# (2026-07-04) and app containers (iCloud~com~microsoft~Office~Excel,
# 2026-07-11..13). App containers (iCloud~*) are app-synced data that lives in
# the vendor's own cloud — excluded wholesale rather than whack-a-mole.
- /Library/Mobile Documents/.Trash/**
- /Library/Mobile Documents/iCloud~*/**
# Keep iCloud Drive proper (com~apple~CloudDocs = the user's real files, kept
# fully downloaded on this machine) — real user data
+ /Library/Mobile Documents/**
# Exclude the rest of ~/Library: app state/caches + the macOS TCC-protected dirs
# (Accounts, Biome, Cookies, HomeKit, Application Support/*, Safari, etc.) that
# the unattended job can't read. Blanket rule so new protected dirs (added by
# macOS updates) never re-break the nightly with 'operation not permitted' (rc=1).
- /Library/**
# Re-downloadable model weights (symlink target on external)
- /.lmstudio/models/**
# AgentsView live SQLite/WAL, bearer tokens, and raw remote mirrors are not
# copied directly. backup/agentsview-snapshot.sh stages a consistent database
# under ~/archives/agentsview, which remains included.
- /.agentsview/**
# Derived DuckDB rebuilt nightly from the source DBs (regenerable)
- /archives/hub/hub.duckdb
- /archives/hub/hub.duckdb.tmp
# msgvault live Gmail credentials. These are OAuth REFRESH TOKENS granting
# ongoing access to both mailboxes — the highest-value credential in ~/archives,
# and the archive itself (msgvault.db, attachments) is backed up around them.
# Excluded rather than kept because the recovery cost is one browser re-auth,
# whereas replicating them puts live mailbox access in the bucket indefinitely.
# 0600 on disk; msgvault regenerates them on re-authentication.
- /archives/email/tokens/**
# NOTE: msgvault-{home,work}-client-secret.json in the same directory are NOT
# yet excluded — deliberately, pending an authoritative copy in 1Password.
# They are Google *installed-app* OAuth clients, which Google does not treat as
# confidential (they ship inside distributed desktop apps) and which are
# re-downloadable from the Cloud console, so they are the weaker half. But the
# token and the client secret are two halves of one working credential, so
# leaving them co-located in the backup is only half a fix. Finish this.
# Agent harness state (~/.claude, ~/.codex). Three separate reasons, kept
# separate because they are NOT equally strong.
#
# 1. CREDENTIALS — never replicate. Live OAuth tokens for Claude/MCP and Codex.
- /.claude/.credentials.json
- /.codex/auth.json
#
# 2. VERBATIM FILE MIRROR — file-history keeps snapshots of every file an agent
#    has edited, so it silently duplicates whatever those files contained. The
#    2026-08-01 sweep found key-bearing files in it. AgentsView does not cover
#    this (it is not agent history), which is what makes it worth excluding.
- /.claude/file-history/**
#    Same class, found while validating these rules: paste-cache holds verbatim
#    pasted prompt text, and every shell-snapshot contains `export VAR=value`
#    lines — an environment dump is a standard secret carrier. Neither is agent
#    history, so AgentsView does not cover either.
- /.claude/paste-cache/**
- /.claude/shell-snapshots/**
#
# 3. AGENT HISTORY — redundant, NOT a secret-exposure fix. AgentsView indexes
#    the mini's Claude/Codex sessions directly and is the system of record, and
#    agentsview-pilot.md states that permanent byte-for-byte native retention is
#    not required. But read that policy's own retention section: AgentsView
#    records contain "credentials accidentally exposed to tools", and
#    ~/archives/agentsview IS backed up. Excluding these removes a duplicate
#    copy; the exposure lives in AgentsView by design. Do not mistake this rule
#    for remediation.
- /.claude/projects/**
- /.codex/sessions/**
#
# 4. JUNK / REGENERABLE / HOT SQLITE. .tmp alone is ~5300 files. The live
#    sqlite+wal sets are excluded for the same reason as ~/.agentsview: a hot
#    WAL copied file-by-file is not a consistent snapshot.
- /.codex/.tmp/**
- /.codex/cache/**
- /.claude/cache/**
- /.codex/*.sqlite
- /.codex/*.sqlite-wal
- /.codex/*.sqlite-shm
#
# NOTE ON CLEANUP: rclone applies filters to BOTH source and destination, so
# adding an exclusion stops future syncing but leaves already-uploaded objects
# ORPHANED in the bucket rather than deleting them. Anything these rules newly
# exclude is still in `bkup:home` until explicitly removed. Verify with
# `rclone lsf bkup:home/.claude/ -R` and purge deliberately with --dry-run
# first; the bucket's 30-day soft-delete then applies to the removal.
# Corollary: this change does NOT retroactively remove the 2026-08-02 TOTP-seed
# transcript from the bucket.
# Junk
- /.Trash/**
- /.cache/**
