# Dotfiles

GNU Stow–managed dotfiles and AI agent platform for macOS and Linux. Each top-level directory is a stow package targeting `~/`.

## Key Commands

- Install everything: `./install.sh`
- Install with macOS apps (casks, Mac App Store): `./install.sh --apps`
- Install open-source tailscaled for incoming SSH (macOS): `./install.sh --tailscale-ssh`
- Skip agent setup: `./install.sh --skip-agents`
- Upgrade all CLIs to latest (reinstall even if present): `./install.sh --upgrade`
- Test on Linux: `./test-install.sh` (Apple Container, Sprite, exe.dev)
- Stow a single package: `stow --no-folding -R -t "$HOME" <package>`
- Dry-run stow: `stow --no-folding -R -n -t "$HOME" <package>`

## Conventions

- Always use `--no-folding` with stow so individual files are symlinked, not directories.
- Secrets stay out of committed files — use 1Password (`op run`) or `.gitignore`d local configs.
- `agents/.agents/AGENTS.md` is the canonical global agent instruction file. `agents/.claude/CLAUDE.md` and `agents/.codex/AGENTS.md` are symlinks to it.
- Skills live in `agents/.agents/skills/` (stow-managed) or `~/.agents/skills/` (git-cloned). Both `~/.claude/skills/` and `~/.codex/skills/` symlink into `~/.agents/skills/`.
- MCP servers use remote HTTP transport. OAuth servers (motherduck, tigris, readwise) work everywhere. GitHub servers (github-home, github-work) use PATs from 1Password (macOS only). `hub-mcp` is the local exception (server code in the private `kylelundstedt/personal-mcp` repo, mini-only): `install.sh` registers the client on personal Macs only — `http://127.0.0.1:8765/mcp` on klundstedt-mini, the tailnet URL on other Macs that can reach it.
- Local config files (`aws/.aws/config`, `git/.gitconfig_local`) are gitignored and created from examples or prompts during install. `~/.ssh/config` is generated by install.sh (not stowed).

## Memory

Durable agent memory lives in this repo as committed files, not in any harness's native store (`~/.claude/…`, Codex/Shelley stores) — only committed-and-pushed content survives machine/VM rebuilds and is visible to every harness. In this repo:

- Open work → `TODO.md` (completed work moves to `CHANGELOG.md`).
- Durable notes — env/tooling gotchas, platform findings, plans, runbooks, rationale, handoff notes → `agent_docs/`, one topic per file, indexed by `agent_docs/README.md`.

## install.sh

The install script sets up a machine from scratch. It self-bootstraps — when piped via `curl | bash`, it installs git, clones the repo to `~/dotfiles`, and re-execs from the cloned copy. If already running from inside the repo, it skips straight to the install steps:

1. **Bootstrap** — (only when not in repo) install git, clone to `~/dotfiles`, re-exec
2. **System deps** — stow, zsh, git, curl (apt on Linux, Homebrew on macOS)
3. **CLI tools** — installed in parallel via curl scripts and GitHub release binaries to `~/.local/bin` (starship, uv, atuin, zoxide, direnv, tigris, archil, fnm, bat, fzf, rg, jq, yq, gh, duckdb, carapace)
4. **Python CLIs** — `uv tool install` for Python-based tools (snowflake-cli → `snow`)
5. **Node** — via fnm (LTS)
6. **Git config** — OS include file, SSH config (macOS: written from scratch — canonicalization + multiplexing + exe.dev key pinning + agent forwarding for `*.ts.net` + 1Password agent; Linux: a marker-managed block PREPENDED to `~/.ssh/config` — GitHub over port 443 + exe.dev key pinning — preserving foreign blocks like iv-image's stanza), exe.dev host key pre-seeded in known_hosts, identity (interactive prompt or default for non-interactive Linux). Commit signing is enabled at login time by `.zshrc` when a forwarded SSH agent is detected.
7. **Shell** — set default shell to zsh
8. **Stow** — all packages (except `ssh`, which is not stowed)
9. **Tailscale** — On Linux: install, start tailscaled (Sprite Service / systemd / bare nohup), authenticate with `--ssh`. On macOS with `--tailscale-ssh`: install open-source tailscale via brew formula, start tailscaled as a system daemon via `sudo brew services`, authenticate with `--ssh`. Without the flag on macOS: expects the standard Tailscale app. Once the brew formula is installed, subsequent runs auto-detect and maintain it. **Host note:** `klundstedt-mini` (always-on Mac mini SSH target) needs `--tailscale-ssh` on its first install; thereafter it self-maintains. `setup_tailscale` installs the formula only if missing and restarts only on CLI/daemon skew — it never runs `brew upgrade`, so formula version bumps (e.g. 1.96 → 1.98) are a manual upgrade ritual. Because `tailscaled` runs as a root system daemon (needs root for the tun device), `sudo brew services` taints each keg with root-owned binaries, so `brew cleanup` can't delete old kegs — the full ritual is: `brew upgrade tailscale` → `sudo brew services restart tailscale` (clears CLI/daemon skew) → `sudo rm -rf /opt/homebrew/Cellar/tailscale/<old-versions>` (cleanup needs sudo for the root-owned binaries).
10. **Agents** — Claude Code CLI, Codex CLI, 1Password CLI (Linux), MCP server registration (remote HTTP, plus the local `hub-mcp` on personal Macs), agent skills
11. **Apps** (only with `--apps`) — `brew bundle` for casks/MAS apps, Sprite CLI, Apple Container CLI, LaunchAgents

**Flags:** `--apps`, `--dry-run`, `--skip-stow`, `--skip-agents`, `--tailscale-ssh`, `--upgrade`

Key properties:

- Idempotent — safe to re-run. By default each tool checks `need <cmd>` and skips if already present (fast re-runs); present tools are never upgraded. Pass `--upgrade` to force a reinstall-at-latest of every CLI (`want <cmd>` = missing OR `--upgrade`). Since the installers always fetch the latest GitHub release / run the vendor install script, forcing a reinstall is the upgrade — no per-tool version parsing.
- Works on macOS and Linux (apt-based)
- Non-interactive mode auto-enabled when not attached to a TTY
